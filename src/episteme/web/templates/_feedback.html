{# Feedback controls for one post. Self-contained and self-replacing: every button swaps this whole block back in, so the rendered state always comes from the database rather than from client-side bookkeeping. `fb` is one context object (web/feedback.py builds it for a single post and for a whole feed page), so the fragment has exactly one contract wherever it is rendered from. `fb.signals` is {kind: feedback_id} for signals already on this post - an active button posts the undo for its own event id, which is exact (the profile is replayed without it), not an approximate reversal. `fb.variant` says which surface this is on, and EVERY hx-post carries it. The fragment replaces itself, so a URL that omits it would let the next render guess - which is exactly how a feed card used to come back wearing the article page's hide-source button. Sits above the card's stretched .card-link via z-index, the same way the provenance link does; on the article page there is no stretched link to clear. It is a bookmark, not a statement about the subject (and it feeds nothing into the profile - see recommend/profile.py). #} {% set direction = "less_topic" if fb.signals.get("dislike") else ("more_topic" if fb.signals.get("like") else none) %}
