{# Reusable UI fragments. Import as: {% import "admin/_macros.html" as ui %} #} {# Render a dict as two-tone key=value chips (muted key, bright value). Nested dicts (e.g. voice params' `prosody`) are flattened with dotted keys, matching the form field labels (`prosody.speed`); flat dicts (job args, source config) pass through unchanged. #} {% macro kv_chips(data, sort=true) -%} {%- if data -%} {{ _kv_inner(data, '', sort) }} {%- else -%} - {%- endif -%} {%- endmacro %} {# The targets a manual job can be pointed at, rendered INSIDE the job's own control so the field sits beside the button that reads it - or once for a whole group, when every job in it takes the same target (admin.SHARED_PARAMS). The button includes `closest .job-run` and/or `previous .job-shared`, so nothing coordinates ids across the page: a field can only ever be read by the job it is inside or by the shared row above it. Which fields exist comes from admin.job_params, i.e. from the same table the API validates against. Never `closest .job-group`: the group is an ancestor of every job in it, so that selector sweeps in each sibling's fields too - see the note on admin._group. `type="text"`, NOT `type="number"`: a number input whose content is not a valid number submits as the EMPTY STRING (HTML spec), so "1o" in a limit field arrived as blank, blank means "everything due", and asking for one item ran the whole backlog with no error anywhere. Text keeps the typo intact so the server can refuse it by name; `pattern` still marks it :invalid before you press anything. `hint` carries the whole explanation because there is no room for a sentence beside a four-character input - so it is both the tooltip and the accessible name, and the visible label is left free to be one word. #} {% macro job_targets(params, extra='') -%} {%- if params -%} {%- for param in params %} {%- endfor %} {%- endif -%} {%- endmacro %} {# Status label as a diff-style badge: dark tinted fill + same-hue border, in the tone the status maps to. succeeded→ok, failed/aborted/cancelled→bad, anything else (todo/doing/running/…) stays neutral. The glyph sits BESIDE the word, never instead of it: this is an operator surface where a misread status is a wrong decision, and the tone mapping is the single source of truth for both the colour and the glyph so they cannot disagree. `doing`/`running` gets the spinner, which is the one place on the site something animates continuously - it is reporting live state. #} {% macro status_badge(value) -%} {%- if value == 'succeeded' -%}{%- set tone, glyph = 'ok', 'ok' -%} {%- elif value in ('failed', 'aborted', 'cancelled') -%}{%- set tone, glyph = 'bad', 'bad' -%} {%- elif value in ('doing', 'running') -%}{%- set tone, glyph = 'neutral', 'running' -%} {%- else -%}{%- set tone, glyph = 'neutral', 'clock' -%} {%- endif -%} {{ ico.icon(glyph, "icon-spin" if glyph == "running" else "") }}{{ value }} {%- endmacro %} {% macro _kv_inner(data, prefix='', sort=true) -%} {%- for key in (data | sort if sort else data) -%} {%- if data[key] is mapping -%} {{ _kv_inner(data[key], prefix ~ key ~ '.', sort) }} {%- else -%} {{ prefix ~ key }}{{ data[key] }} {%- endif -%} {%- endfor -%} {%- endmacro %}
